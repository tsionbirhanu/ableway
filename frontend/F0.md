Accessibility UI rules. Follow them in every component and page. Standard: WCAG 2.2 AA at minimum, AAA contrast where possible. Users are blind or visually impaired, and many are new to computers.

Structure and semantics
1. Use native HTML first (button, a, input, select, label, fieldset, legend, table, dialog). Use ARIA only when no native element exists, and never add a role that conflicts with the element.
2. Every page has a lang attribute, one h1, headings in order with no skipped levels, landmarks (header, nav, main, footer), and a skip link to main as the first focusable element.
3. Navigation and the Help link are in the same place on every page.
4. Every page has a unique descriptive title, such as "Choose a course - [Platform name]".

Keyboard and focus
5. Everything works by keyboard alone in a logical order. No keyboard traps. No positive tabindex.
6. Every control has a visible focus indicator: 3px outline with 2px offset, 3:1 contrast against its surroundings, never removed. Sticky bars must not hide the focused element.
7. On route change, move focus to the new page's h1 (tabindex=-1) and announce the page name in a polite live region.
8. Dialogs move focus in, trap it, close with Escape, and return focus to the trigger.
9. Single-key shortcuts must be switchable off or remappable. Use modifier combinations (such as Alt+Shift+key) and list them on the Help page.

Visual design
10. Text contrast is at least 4.5:1 (7:1 in the high contrast theme). Interface parts and focus indicators are at least 3:1. Never use colour alone to carry meaning; add text or an icon with an accessible name.
11. Provide three themes: default, high contrast, and large text (up to 200%). Layouts must work at 400% zoom without scrolling in two directions. Use rem units and responsive layouts.
12. Click and touch targets are at least 44 by 44 CSS pixels, with spacing between them.
13. Respect prefers-reduced-motion. No autoplaying media, no flashing, and no moving content that cannot be paused.
14. Never rely on hover. No drag-only actions; always provide a button alternative.

Forms and errors
15. Every input has a visible, persistent label (never a placeholder alone), the right type, and an autocomplete attribute. Group related fields with fieldset and legend. Mark required fields with the word "required".
16. On submit errors, show a summary at the top (role="alert") and move focus to it. Also show a message next to each field, linked with aria-describedby and aria-invalid. Say what to do, for example "Enter an email like name@example.com".
17. Do not make users enter the same information twice. Authentication must not need puzzles or CAPTCHAs, must allow paste and password managers, and should use one-time codes.
18. No time limits. If a session will expire, warn in text and audio and let the user extend it.

Dynamic content and audio
19. Use one shared LiveRegion component. Status changes use aria-live="polite"; use "assertive" only for urgent errors. Messages are short and never repeated.
20. The assistant has two modes. Voice mode: the app speaks. Screen reader mode: the app never speaks; it writes to live regions and the screen reader reads them. Never speak over a screen reader. The user chooses the mode at the start and in settings.
21. Audio always has controls (play, pause, back 10 seconds, speed, volume) and a text transcript. Audio never starts without a user action, except the welcome after an explicit Start button.
22. Every non-text item (image, chart, icon) has a text alternative. Decorative items are hidden (alt="" or aria-hidden).

Content
23. Use plain language, short sentences, and a reading level around grade 6. Offer at most five options at once. Say what will happen before an action.
24. Use tables only for data, with th, scope, and a caption. Use real ul and ol lists.
25. Set lang on the page and on any text in another language, and update it when the learner switches language.

Testing for every component
26. Add axe tests (vitest-axe) and Playwright keyboard-only tests, and fail CI on violations. Check manually with NVDA and Firefox, JAWS and Chrome, VoiceOver and Safari, TalkBack and Chrome, and at 400% zoom.
